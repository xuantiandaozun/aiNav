| 项 | 内容 |

本文描述要做成什么、做到什么算完成。实现时遵守本文的对象、状态和验收标准。

## 1. 背景与目标

中文用户找 AI 工具时，导航站、新闻和「别人怎么用 AI 赚钱」分散在不同网站。本产品把这三件事放在同一个中文站点里。

目标：

1. 访客能在一个站点里看当天 AI 热点、按场景找到工具、阅读经过整理的副业案例。
2. 热点、工具、案例用同一套场景标签连在一起，从案例能走到它用过的工具，从热点能走到相关工具。
3. 第一期月运营现金成本为 0 元（域名年费除外）。界面与对外文案使用简体中文。

成功标准（第一期上线后即可观察，不作为开发完成的阻塞项）：

- 访客不注册就能完成「看一条热点并打开原文」「按场景打开一个工具官网」「读完一个案例并打开它用到的工具」。
- 热点每天自动更新，站长不用手工粘贴新闻。
- 案例在人工确认前不会出现在公开页面。

## 2. 用户与要完成的事

第一期只有两种人。

### 2.1 访客

不注册、不登录。来站点是为了办完下面某件事就离开，或顺便再看一条。

| 编号 | 要完成的事 | 办完的标志 |
| --- | --- | --- |
| V1 | 用几分钟看完今天的 AI 动态 | 打开至少一条热点的原文 |
| V2 | 按自己的场景找到能用的工具 | 知道这个工具做什么、要不要付钱、国内能不能直接打开，并前往官网 |
| V3 | 判断一个副业自己能不能做 | 看清场景、用到的工具、时间成本，以及收入说法的出处 |

访客使用简体中文。页面在手机和桌面浏览器都能完成上述三件事。

### 2.2 站长

第一期的唯一操作者，就是站点维护者本人。站长要完成：

| 编号 | 要完成的事 | 办完的标志 |
| --- | --- | --- |
| O1 | 让热点每天自己进来 | 定时任务写入新热点，首页能看到 |
| O2 | 收录或下线一个工具 | 公开列表里的工具都是确认过官网可用的 |
| O3 | 审一条副业案例 | 草稿不会公开；确认后的案例能被访客读到，并链到工具 |
| O4 | 控制花费 | 日常运行不产生云服务器、数据库或对话模型账单 |

第一期站长不使用登录后台。工具和案例用仓库里的数据文件维护；热点由定时任务写入数据文件。

## 3. 产品边界

一个站点，三个公开栏目。

| 栏目 | 访客用它来 | 内容从哪来 | 谁决定公开 |
| --- | --- | --- | --- |
| 热点 | 看当天 AI 动态并跳到原文 | 公开 RSS 定时采集 | 符合采集规则的条目自动公开 |
| 导航 | 按场景找工具并前往官网 | 站长维护；采集只可产生候选 | 站长确认后公开 |
| 案例 | 看一种副业怎么做、用哪些工具 | 公开来源进草稿，站长改写成短评 | 站长确认后公开 |

三条线共用场景标签：写作、绘图、视频、编程、办公。一条内容可以有多个标签。

### 3.1 本期要做

- 简体中文静态站点：首页、热点列表、工具列表、工具页、案例列表、案例页。
- 热点定时采集、去重、自动公开。
- 工具与案例的数据文件维护方式，以及案例草稿与公开的区分。
- 从案例到工具、从热点到相关工具的跳转。
- 来源署名、收入说法的固定写法、页脚说明。

### 3.2 本期不做

这些留到有稳定访问之后再单独立项，不进第一期验收。

- 站内对话机器人、自动生成长文、付费摘要。
- 访客注册、评论、投稿、支付、广告位。
- 登录后台。
- ICP 备案与中国大陆加速节点。
- 全文转载，以及登录后才能看的页面抓取。

## 4. 信息架构

```text
首页 /
├── 热点 /news
├── 导航 /tools
│   └── 工具页 /tools/{slug}
└── 案例 /cases
    └── 案例页 /cases/{slug}
```

首页同时给出三条入口，每条入口展示少量最新内容，并链到对应列表。

全局导航固定为：首页、热点、导航、案例。当前栏目有明确的选中状态。

站内搜索放在第二期。第一期访客用栏目和场景标签缩小范围。

## 5. 领域对象

访客能认出的东西只有四类：热点、工具、案例、场景。标识、采集时间和原始报文是系统自己用的，不出现在页面上。

### 5.1 场景

固定五个，第一期不让访客或采集任务新增场景。

| 标识 | 展示名 | 用来归什么 |
| --- | --- | --- |
| writing | 写作 | 文案、文章、翻译、办公写作 |
| image | 绘图 | 图片生成与修改 |
| video | 视频 | 视频生成、剪辑、数字人 |
| coding | 编程 | 写代码、改代码、开发助手 |
| office | 办公 | 表格、演示、会议、通用效率 |

### 5.2 热点

一条热点是某篇公开报道在本站的索引，不是文章副本。

| 字段 | 含义 | 谁提供 | 公开页面是否展示 |
| --- | --- | --- | --- |
| title | 标题 | 来源 RSS | 是 |
| sourceName | 来源名称，如「量子位」 | 采集配置 | 是 |
| sourceUrl | 原文地址 | 来源 RSS | 作为「阅读原文」的链接 |
| publishedAt | 原文发布时间 | 来源 RSS | 是 |
| excerpt | 短摘要，最长 140 个汉字 | 优先用 RSS 自带摘要，截断；没有摘要则留空 | 有则展示 |
| scenes | 场景，零到多个 | 采集按关键词归类，归不上就为空 | 有则展示 |
| collectedAt | 采集时间 | 系统 | 否 |

不保存正文。同一原文地址只保留一条。

### 5.3 工具

一个工具是访客可以离开本站去使用的产品。

| 字段 | 含义 | 谁提供 | 公开页面是否展示 |
| --- | --- | --- | --- |
| name | 名称 | 站长 | 是 |
| slug | 地址用的短名，创建后不改 | 站长 | 只出现在网址中 |
| summary | 一句话说明它做什么 | 站长 | 是 |
| websiteUrl | 官网地址 | 站长 | 作为「打开官网」 |
| scenes | 场景，至少一个 | 站长 | 是 |
| price | 免费、部分免费、付费，三选一 | 站长 | 是 |
| access | 国内可直接打开、打开不稳定，二选一 | 站长按自己的网络实测填写 | 是 |
| status | 草稿、公开、已下线 | 站长 | 访客只看见「公开」 |
| note | 补充说明，可空 | 站长 | 工具页展示 |
| featured | 是否放在首页常用区 | 站长 | 否。只影响首页排序 |

价格和网络情况过期时，由站长改数据后重新发布。页面展示的是站长最后一次确认的说法，并带上数据里的更新时间。

### 5.4 案例

一个案例是站长写的短评，用来帮访客判断一种副业能不能做。它指向原文，也指向本站工具。

| 字段 | 含义 | 谁提供 | 公开页面是否展示 |
| --- | --- | --- | --- |
| title | 案例标题 | 站长 | 是 |
| slug | 地址用的短名 | 站长 | 只出现在网址中 |
| scene | 一个主场景 | 站长 | 是 |
| summary | 这种方法在做什么 | 站长 | 是 |
| tools | 用到的本站工具，至少一个 | 站长从已公开工具里选 | 是，可点进工具页 |
| timeCost | 时间成本，用站长的话描述 | 站长 | 是 |
| incomeClaim | 收入说法的转述 | 站长转述来源，不写成站点核实结果 | 是，固定前缀见 7.3 |
| sourceName | 来源名称 | 站长 | 是 |
| sourceUrl | 原文地址 | 站长 | 作为「查看来源」 |
| status | 草稿、公开、已撤回 | 站长 | 访客只看见「公开」 |
| publishedAt | 公开时间 | 首次改为公开时由系统或站长填写 | 是 |

采集任务可以生成一条草稿的素材（来源标题、链接、时间），不能直接生成访客可见的案例正文。

## 6. 状态与谁能改

### 6.1 热点

采集写入后即为公开。没有草稿状态。

超过 14 天的热点仍留在热点列表里，按时间排序自然沉下去。首页只取最近的条目。站长可以删除明显重复或与 AI 无关的条目，删除后公开页面不再出现。

### 6.2 工具

```text
草稿 → 公开 → 已下线
公开 → 草稿   （发现信息有误，先从公开列表拿掉）
已下线 → 公开 （官网恢复后）
```

只有「公开」出现在首页、工具列表、工具页，以及案例页的工具链接里。案例如果引用了已下线工具，案例页仍保留工具名称，并标明「已下线」，链接不再作为主要行动。

### 6.3 案例

```text
草稿 → 公开 → 已撤回
公开 → 草稿   （需要改写时先撤回公开）
```

草稿和已撤回对访客不可见，直接访问其地址时显示「这条内容还没有公开」，不泄露正文。

## 7. 内容规则

### 7.1 热点可以自动写入的范围

初始来源（可配置，第一期至少接通这些公开 RSS）：

| 来源 | 地址 |
| --- | --- |
| 机器之心 | https://www.jiqizhixin.com/rss |
| 量子位 | https://www.qbitai.com/feed |
| 36氪 | https://www.36kr.com/feed |
| InfoQ 中文 | https://www.infoq.cn/feed |

写入条件：

- 有标题和原文地址。
- 原文地址未曾入库。
- 标题或摘要能对应到 AI、大模型、智能体、AIGC 之一；对不上的条目丢弃，不进公开列表。
- 摘要若超过 140 个汉字，截断并加省略号。摘要里的 HTML 去掉。

采集频率：每天 2 次。某一次失败不影响已公开内容，下一次继续。失败要在任务日志里留下来源名称和原因，不在访客页面展示报错。

### 7.2 工具的公开条件

公开前必须同时满足：名称、一句话说明、官网地址、至少一个场景、价格、网络情况。官网地址使用 https。站长在公开前自己打开过该官网。

### 7.3 案例的公开条件与写法

公开前必须同时满足：标题、主场景、方法说明、至少一个状态为「公开」的工具、时间成本、收入说法、来源名称、来源地址。

收入说法在页面上固定带这个前缀，不能删：

> 来源声称：

前缀后面是站长的转述，例如「来源声称：作者在文中写道，试做两周后接到 3 单。」站点不把收入写成已核实事实。来源没有提到收入时，填写「来源未说明收入」，前缀仍然保留。

案例正文由站长自己写，不粘贴原文段落。页面提供「查看来源」。

### 7.4 禁止采集和禁止发布

- 不抓取需要登录、验证码或付费后才能看的页面。
- 不保存新闻或案例的全文。
- 不把课程、提示词包、社群广告当作案例发布。
- 不发布没有原文链接的收入数字。

## 9. 运行约束

这些约束和功能需求一样要满足。

| 编号 | 约束 |
| --- | --- |
| NFR-01 | 第一期月运营现金成本为 0 元。允许的外部花费只有域名年费。 |
| NFR-02 | 站点为静态页面。访客打开页面时不调用对话模型，不连接需要按月付费的数据库。 |
| NFR-03 | 热点采集放在定时任务里。第一期使用公开代码仓库的定时任务，把结果写回数据文件再发布静态页。 |
| NFR-04 | 静态站点托管在提供免费额度、且「不含中国大陆加速」时可以不备案的平台。第一期不购买中国大陆加速，不做 ICP 备案。 |
| NFR-05 | 页面在国内网络下应当能够打开。速度不作为第一期验收门槛。若后来访问稳定，再单独立项备案和大陆节点，不在本期范围。 |
| NFR-06 | 单个采集任务在来源无响应时应在有限时间内结束，避免一次挂死拖住全部来源。建议单路超时 20 秒。 |
| NFR-07 | 数据文件可以放在公开仓库。其中不含密钥、账号和收入核实材料。 |

第一期推荐形态（实现时按此选型，除非有同等成本的替代并写进变更记录）：

- 站点：静态生成，托管于 EdgeOne Pages 免费版，加速区域为全球且不含中国大陆。
- 采集：公开 GitHub 仓库的 Actions，每天 2 次。
- 若采集必须改到云函数：使用 EdgeOne Cloud Functions 的免费额度，页面仍保持静态。不使用仅有约 10 毫秒 CPU 的免费边缘函数做多路抓取，也不把腾讯云函数的三个月试用额度当作长期方案。

## 10. 第一期初始内容

上线时数据不能是空壳。站长在发布前准备：

- 至少 40 个状态为公开的工具，五个场景都有工具。
- 至少 12 个状态为公开的案例，每个案例至少链到 1 个已公开工具。
- 热点由第一次成功的采集任务填入。若采集当日来源为空，首页热点区按 FR-H-05 显示空状态，不阻塞工具和案例上线。

工具和案例的具体名单不在本文锁定，由站长按第 7 节的公开条件挑选。

## 11. 验收

第一期全部 P1 需求实现后，按下面的路径检查。路径走通才算第一期完成。

1. 打开首页。能看出三件事，并进入三个列表。
2. 在热点列表用一个场景筛选，打开一条「阅读原文」，浏览器进入来源站点，本站没有复制全文。
3. 在导航里筛选「写作」，进入一个工具页，看到价格和网络情况，点击「打开官网」。
4. 打开一个案例，看到「来源声称：」，点击其中一个工具进入工具页，再点击「查看来源」进入原文。
5. 把一条案例改回草稿并重新发布后，原地址不再显示正文；公开列表里没有它。
6. 连续运行两次采集。第二次不产生同一原文地址的重复热点。断开其中一路来源时，其余来源仍能写入。
7. 用手机宽度查看首页和三个列表，主按钮无需横向拖动页面才能点到。
8. 检查运行账单：除域名外，没有为这个站点购买按月付费的服务器、数据库或模型接口。
